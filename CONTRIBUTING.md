# Contributing to GoreeCloud Suite documentation

This repository is the shared portfolio and documentation hub for GoreeCloud Suite.

## Change workflow

1. Identify the authoritative source for the proposed change.
2. Create a focused branch.
3. Update the smallest set of files needed.
4. Preserve links to the underlying repository or Drive record.
5. Review privacy and security boundaries.
6. Open a draft pull request.
7. Merge only after content, links, and classification are verified.
8. Update the applicable Drive record or change log when approved scope or current state changes.

## Writing expectations

- Prefer plain language and specific product roles.
- Distinguish implemented, accepted, transitional, planned, and aspirational work.
- Do not present repository presence as proof of production readiness.
- Keep summaries concise and link to the authoritative record.
- Avoid duplicating volatile details across multiple files.
- Use first-person voice only when the page intentionally represents the owner's position.
- Preserve product names and relationships defined by the Suite overview.

## Link expectations

- Use canonical GitHub repository links.
- Use canonical Google Drive, Docs, and Sheets links observed from the connected account.
- Do not invent file IDs, repository names, releases, deployment state, or public URLs.
- Private Drive links remain access controlled and do not change sharing permissions.

## Review checklist

- [ ] Product role and category are accurate.
- [ ] Repository visibility and links are current.
- [ ] Claims are supported by the most specific authoritative source.
- [ ] Planned work is not described as completed.
- [ ] No secret, sensitive, or personal information is exposed.
- [ ] No duplicate uncontrolled source of truth was created.
- [ ] Navigation remains consistent across README, portfolio, and reference pages.
- [ ] Relevant implementation and Drive records are updated together.

## Security

Read [docs/SECURITY-BOUNDARIES.md](docs/SECURITY-BOUNDARIES.md) before moving internal content to any public repository or website.
