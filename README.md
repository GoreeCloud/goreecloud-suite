# GoreeCloud Suite

GoreeCloud Suite is the integrated application and service ecosystem within GoreeCloud, a privacy-first, self-hosted personal and family cloud platform.

The Suite brings together software for productivity, knowledge, communication, storage, media, identity, security, networking, administration, backup, recovery, and digital preservation. Its purpose is to provide a coherent experience without giving up data ownership, portability, recoverability, or long-term control.

## Portfolio snapshot

- 37 GitHub repositories: 26 public and 11 private.
- 25 top-level GoreeCloud Drive categories.
- 26 current application specifications, project records, and portfolio references in the project catalog.
- One shared design language: Glaze UI.

## Platform relationship

GoreeCloud is the full governed platform: ownership, infrastructure, networking, virtualization, runtime, data, backup, identity, security, privacy, standards, policies, operations, and succession.

GoreeCloud Suite is the user-facing and administrator-facing application ecosystem inside that platform.

Shared product foundations include:

- Glaze UI for design and interaction.
- GoreeCloud Identity for authentication and single sign-on where appropriate.
- Wardveil Security by GoreeCloud for security and protection identity.
- GoreeCloud Privacy Shield for privacy identity and privacy-control foundations.
- Everkeep for continuity, backup, recovery, preservation, portability, succession, and digital legacy.

## Source-of-truth rule

This repository is a portfolio and navigation layer. It does not replace the authoritative records maintained in individual application repositories and the GoreeCloud Drive hierarchy.

When records differ, use the most specific current source:

1. Application repository for source, release, and implementation state.
2. Project specification for approved product scope.
3. Architecture record for system relationships and boundaries.
4. Policy, standard, or requirement for governing rules.
5. Inventory for current operational facts.
6. Change log for historical evidence.

## Privacy and safety

Public summaries must never expose credentials, tokens, private keys, recovery codes, private network details, sensitive inventories, personal information, or internal-only configuration merely to make the portfolio appear complete. See [Security boundaries](docs/SECURITY-BOUNDARIES.md).
